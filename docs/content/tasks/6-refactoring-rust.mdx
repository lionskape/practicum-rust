# Проект модуля 6. Рефакторинг кода на Rust

## Инфраструктура проекта

В этом репозитории решение размещено в `crates/analysis`. Проект взят из исходного задания
Практикума и подключён к общему Cargo workspace.

Исходный архив задания:

- [analysis-project.zip](https://code.s3.yandex.net/middle-rust-blockchain/analysis-project.zip?etag=cca1276008fd1916ce177ae1fd8d1566)

## Описание

Цель проекта - провести рефакторинг существующего Rust-кода, сохранив прежнее поведение,
работоспособность бинарника и тесты. В коде есть подсказки с местами, где нужно заменить
неидиоматичные решения на более простые и безопасные.

Проверяемые проблемы:

- лишние вызовы `clone()` вместо ссылок;
- использование `Rc<RefCell<T>>` там, где достаточно обычного владения или заимствования;
- циклы вместо итераторов;
- `unsafe` без необходимости;
- singleton, без которого можно обойтись;
- излишняя валидация вместо tight-типов;
- дублирование кода вместо дженериков;
- трейт-объекты там, где подходят дженерики;
- цепочки `if` вместо `match`;
- enum-варианты, занимающие слишком много места на стеке;
- паника вместо возврата ошибки.

## Решение в этом репозитории

Исправленный crate:

- `crates/analysis`

Основные изменения:

- поток чтения логов переписан без `Rc<RefCell<_>>`, trait object и `unsafe`;
- режимы чтения представлены enum-типом вместо числовых констант;
- фильтрация логов выражена через итераторы и `match`;
- парсеры параметризованы через дженерики там, где раньше был дублирующийся код;
- крупные enum-варианты вынесены в `Box`, чтобы уменьшить размер enum на стеке;
- singleton-парсер заменён на обычное создание parser value;
- panic в библиотечном API заменён на возвращаемую ошибку.

## Проверка

Основные команды:

```bash
cargo test -p analysis -- --nocapture
cargo run -p analysis --bin cli -- crates/analysis/example.log
cargo ci
```
